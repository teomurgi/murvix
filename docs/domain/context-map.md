# Context map and integration authority

[Domain reference](README.md) · [Subdomains](subdomains.md) · [Domain model](domain-model.md)

## Finding

**Inferred:** the strongest model distinction is **server-owned terminal work and project registration** versus **client-owned workspace presentation**. Extension hosting and executable/profile maintenance add candidate boundaries with different trust and lifecycle rules. These are analytical candidates, not claims that Murvix follows DDD or has separate owning teams.

**Observed:** one wire `ProjectDescriptor` is translated into a desktop `Project` containing tabs and availability; catalog refresh overlays pending local metadata edits while preserving local view state. The TUI uses its own smaller `Project` model and storage. See [crates/murvix-protocol/src/project.rs:87–116](../../crates/murvix-protocol/src/project.rs#L87-L116), [crates/murvix-app-core/src/catalog.rs:214–316](../../crates/murvix-app-core/src/catalog.rs#L214-L316), and [crates/murvix-cli/src/state.rs:18–58,598–670](../../crates/murvix-cli/src/state.rs#L598-L670).

## Candidate internal boundaries

| Candidate | Model and authority | Boundary rationale and uncertainty |
| --- | --- | --- |
| Persistent workspace | Server catalog, Home/worktree relationships, session membership and history, shared activity, server settings and paired-device state. | **Observed:** server resolves project IDs into its own filesystem and serializes session mutation through session ownership. **Inferred:** a coherent authority boundary, although Git/files/access share the same server and are not proven independent bounded contexts. See [model](domain-model.md), [rules](business-rules.md). |
| Workspace presentation | Desktop project projection, tabs/panes/groups/focus, composer drafts, browser panes and settings. TUI maintains a separate terminal-only view model. | **Observed:** desktop state and TUI state have different shapes and files; both reference server identities/sessions. **Inferred:** model translations support a presentation boundary; not evidence of distinct organizations or a strict isolation layer. [crates/murvix-app-core/src/state.rs:14–58](../../crates/murvix-app-core/src/state.rs#L14-L58), [crates/murvix-cli/src/state.rs:18–64](../../crates/murvix-cli/src/state.rs#L18-L64). |
| Extension host | Manifest identity, contributions, permission decisions, installed packages, script/webview lifecycle and extension events. | **Inferred:** explicit translation from extension API into host operations supports a candidate integration boundary. It is not a tenant boundary or an assertion of sandbox completeness. Canonical constraints: [BR-12](business-rules.md#br-12-extension-authority). |
| Profile and executable maintenance | Configuration import/restore, package/build identity, update compatibility and runtime leases. | **Inferred:** distinct lifecycle and consistency concerns justify discussing it separately; a separately bounded domain model is **Not established**. See [WF-09](workflows.md#wf-09-personalize-back-up-and-restore-a-profile), [WF-10](workflows.md#wf-10-install-and-replace-executables). |

No reliable evidence establishes a separate bounded context for each crate, each UI view, each Git command, or each supported agent. Relationship labels such as partnership, customer/supplier, conformist, and published-language team agreement are **Not established**. A shared protocol alone does not establish those agreements.

## Exchanges, translation, and data authority

| Direction | Exchanged concepts and translation | Authority and material limits |
| --- | --- | --- |
| Desktop/TUI/CLI → selected server; server → clients | Typed requests carry project/session/operation IDs and byte-valued `ServerPath`; replies, metadata, frames, lifecycle messages and revision invalidations return. Desktop translates descriptors into cached views; TUI reconciles its own project-indexed layout. | **Observed:** server owns registration and execution; clients own layouts. Session IDs must be scoped to a server. Project metadata may be optimistically overlaid, not globally committed at client edit time. [crates/murvix-app-core/src/servers.rs:1–26](../../crates/murvix-app-core/src/servers.rs#L1-L26), [crates/murvix-app-core/src/catalog.rs:139–179,214–264](../../crates/murvix-app-core/src/catalog.rs#L214-L264). |
| Client → SSH process → remote `murvix stdio` → remote local socket | Remote command readiness and byte relay transport the same server protocol; the remote account's filesystem paths remain remote paths. | **Observed:** SSH bridge gains ordinary local-client server authority; it does not authenticate as a paired device. SSH host/account/key trust belongs to SSH and client configuration. [crates/murvix-client/src/ssh.rs:29–156,191–251,309–352](../../crates/murvix-client/src/ssh.rs#L29-L156), [crates/murvix-client/src/bridge.rs:48–96](../../crates/murvix-client/src/bridge.rs#L48-L96). |
| Paired client → TLS listener → device-authorized connection | Certificate fingerprint pins server identity; application-layer pair/authenticate exchanges establish a device credential. No client-certificate identity is implied. | **Observed:** TLS 1.3, certificate-DER pinning, pair/authenticate first-request requirement and device policy. This is a different trust boundary from SSH. [crates/murvix-protocol/src/transport/tls.rs:26–63,237–324](../../crates/murvix-protocol/src/transport/tls.rs#L237-L324), [crates/murvix-server/src/connection/auth.rs:27–90](../../crates/murvix-server/src/connection/auth.rs#L27-L90). |
| Server → PTY/shell/program; output → terminal engine → clients/archive | Input bytes/structured keys, dimensions and terminal output become screen rows, history, prompt/progress metadata and best-effort agent status. | **Observed:** operating system/program owns actual process execution; Murvix owns terminal representation and persistence. Server restart does not restart the program. See [WF-02](workflows.md#wf-02-share-close-detach-and-restore-terminals). |
| Server → Git → repository/remotes | Catalog project selects directory; Git results become status/diff/branch/worktree values. A repository-common-directory lock coordinates Murvix Git paths. | **Observed:** Git/filesystem remain authoritative for checkout state; Murvix owns registration and operation receipts. Locks do not cover external Git writers. [crates/murvix-server/src/git/mod.rs:42–151](../../crates/murvix-server/src/git/mod.rs#L42-L151). |
| Server → installed `gh` → GitHub; JSON → protocol values | PR metadata, checks, diffs, merges, branch updates and PR checkout tracking are translated into local project workflows. | **Observed:** GitHub owns PR metadata; Git owns commits/branches; Murvix can report partial success after remote side effects. [crates/murvix-server/src/git/github.rs:20–326,527–622](../../crates/murvix-server/src/git/github.rs#L20-L326). Live authentication/service availability is **Not established**. |
| Client/extension → server file/exec APIs | Project-relative paths drive file operations; uploaded files return absolute temporary paths; exec returns bounded output and completion state. | **Observed:** file API root confinement is not a global shell/exec sandbox. Exec allows an overridden cwd; paired clients cannot use dedicated exec but can operate terminals. [crates/murvix-server/src/files/root.rs:35–163](../../crates/murvix-server/src/files/root.rs#L35-L163), [crates/murvix-server/src/exec.rs:38–122](../../crates/murvix-server/src/exec.rs#L38-L122), [crates/murvix-server/src/connection/policy.rs:7–74](../../crates/murvix-server/src/connection/policy.rs#L7-L74). |
| Browser CLI → local desktop `app.sock` → browser host | One JSON request/reply translates browser operations to app-owned panes/native WebKit. This bypasses the terminal server because it has no browser model. | **Observed:** CLI browser dispatch is local-app automation and rejects `--host`; only open may start an app. [crates/murvix-cli/src/browser/mod.rs:24–70](../../crates/murvix-cli/src/browser/mod.rs#L24-L70), [crates/murvix-cli/src/args.rs:38–77](../../crates/murvix-cli/src/args.rs#L38-L77). Runtime native behavior is **Not established**. |
| Extension script/webview → host dispatcher → app/server or network | Declared operations become permission-checked host requests; terminal/file/Git/process actions reach the selected server, while permitted HTTP runs in the app. | **Observed:** API and HTTP trust rules; [BR-12](business-rules.md#br-12-extension-authority). External extension code is outside this repository's first-party model. |
| Desktop → installed AI tool → result text | Prompts and repository context request commit/PR metadata; provider-specific startup commands can resume an agent transcript session. | **Observed:** first-party orchestration, not first-party model inference or a separate implemented AI code-review action. No guarantee of answer quality or agent task completion; [WF-04](workflows.md#wf-04-observe-and-acknowledge-agent-activity), [WF-05](workflows.md#wf-05-work-on-git-and-worktrees). |
| Desktop → OS/native services | Clipboard, file opener, notifications, global shortcut, voice, themes and webviews adapt workspace intent to platform services. | **Observed:** supported/unavailable/unsupported are separate capability states, [crates/murvix-core/src/capability.rs:63–94](../../crates/murvix-core/src/capability.rs#L63-L94). Availability and successful user permissions are **Not established** by source. |
| Maintainer/update client → release/distribution endpoints → installation | Version/build identity and verified package artifacts become installed executable sets. | **Observed:** implemented release/update paths; [WF-10](workflows.md#wf-10-install-and-replace-executables). Current publication, signatures and endpoint responses are **Not established**; no live systems were accessed. |

## Consistency across boundaries

**Observed:** desktop catalog application clones/merges/validates before replacing the current state. The desktop persistence writer uses a locked temporary file, sync, rename and directory sync. The TUI locks and rereads a shared document, validates a proposed change and blocks further effects if recovery after save failure fails. These are local boundaries, not a transaction with a server, repository, shell, or remote service. See [crates/murvix-app-core/src/catalog.rs:231–238](../../crates/murvix-app-core/src/catalog.rs#L231-L238), [crates/murvix-app-core/src/store.rs:50–97](../../crates/murvix-app-core/src/store.rs#L50-L97), [crates/murvix-cli/src/state.rs:641–670](../../crates/murvix-cli/src/state.rs#L641-L670).

**Observed:** protocol `Changed`, `GitChanged` and `FilesChanged` notify clients to refresh or inspect data; desktop delivery coalesces redundant pending invalidations. These are integration messages, not proof of a persisted, ordered domain-event stream. See [crates/murvix-protocol/src/message.rs:15–89](../../crates/murvix-protocol/src/message.rs#L15-L89), [crates/murvix-app/src/boot/delivery.rs:30–97](../../crates/murvix-app/src/boot/delivery.rs#L30-L97).
