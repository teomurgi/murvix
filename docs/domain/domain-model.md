# Domain model and consistency boundaries

[Domain reference](README.md) · [Glossary](glossary.md) · [Rules](business-rules.md) · [Workflows and events](workflows.md)

DDD classifications below describe evidence-supported behavior, not the developers' stated design method.

## Identity and lifecycle

### Project

**Observed:** a server `ProjectDescriptor` has a UUID-backed `ProjectId` independent of its folder/name. Mutable metadata includes name, icon/logo/color and extra workspace directories; Home and parent/kind distinguish lifecycle roles. The server validates map-key identity and session ownership, while ordinary registration permits distinct projects to point at the same directory. See [crates/murvix-protocol/src/project.rs:67–116](../../crates/murvix-protocol/src/project.rs#L67-L116), [crates/murvix-server/src/catalog/mod.rs:103–144](../../crates/murvix-server/src/catalog/mod.rs#L103-L144), and `mutations::create` in [crates/murvix-server/src/catalog/mutations.rs:106–139](../../crates/murvix-server/src/catalog/mutations.rs#L106-L139).

**Inferred — entity:** identity persists through metadata changes and removal, rather than being derived from attributes. Home is a protected project role, not a separate account. A worktree project is both a registration and a Git checkout relationship; deleting the registration is not equivalent to deleting files.

**Observed lifecycle:** register → patch/use → mark deleting and hide → end/discard memberships → remove descriptor. Deletion marks direct children too; cleanup is resumable rather than one filesystem/process transaction. [crates/murvix-server/src/catalog/mutations.rs:8–103](../../crates/murvix-server/src/catalog/mutations.rs#L8-L103), [crates/murvix-server/src/registry.rs:240–255](../../crates/murvix-server/src/registry.rs#L240-L255). Worktree creation/removal has its own receipt workflow in [WF-05](workflows.md#wf-05-work-on-git-and-worktrees).

The desktop `Project` is a **projection plus local state**, not the server entity copied without translation. It retains tabs/groups, a client timestamp and availability. `apply_catalog` overlays pending edits and preserves existing tabs; missing remote connections are distinct from missing folders. [crates/murvix-app-core/src/project.rs:70–165](../../crates/murvix-app-core/src/project.rs#L70-L165), [crates/murvix-app-core/src/catalog.rs:214–316](../../crates/murvix-app-core/src/catalog.rs#L214-L316).

### Terminal session

**Observed:** `SessionInfo` fixes ID, owning project and initial directory; mutable title/current directory/foreground process live in `SessionMetadata`. Shell directory changes do not transfer project membership. [crates/murvix-protocol/src/session.rs:46–64,212–220](../../crates/murvix-protocol/src/session.rs#L212-L220), [crates/murvix-server/src/session/metadata.rs:41–105](../../crates/murvix-server/src/session/metadata.rs#L41-L105).

**Inferred — entity:** a session remains the same terminal through attachments, resizes, changing programs and retained-output lifecycle. Its identity must be qualified by server; app-core keeps session-keyed state per server. [crates/murvix-app-core/src/servers.rs:1–26](../../crates/murvix-app-core/src/servers.rs#L1-L26).

**Observed lifecycle:** durable reservation/`Starting` → spawn → `Live` → natural/explicit termination → `Ended` when an archive file exists, otherwise `Unavailable` → discard/retention removes membership/content. Failed spawn and startup recovery can yield unavailable records without a running process. An existing archive can be corrupt, so `Ended` does not certify readable saved output. [crates/murvix-server/src/catalog/sessions.rs:21–120](../../crates/murvix-server/src/catalog/sessions.rs#L21-L120), [crates/murvix-server/src/catalog/mod.rs:223–253](../../crates/murvix-server/src/catalog/mod.rs#L223-L253), [crates/murvix-server/src/archive.rs:184–194,311–328](../../crates/murvix-server/src/archive.rs#L311-L328).

Session “owner” is the earliest connected participating client, a display label rather than exclusive input or elevated permission. References, pending creations and attachments count toward participation. Connections can share one terminal and its size; explicit end/discard can affect all viewers. [crates/murvix-server/src/registry.rs:163–209,675–799](../../crates/murvix-server/src/registry.rs#L163-L209).

### Local view identities

**Observed:** `TabId`, `GroupId` and `PaneId` are UUIDs; a pane's content/title and a tab's title/color/pin/layout/zoom can change without replacing their identity. A terminal pane may initially have no session. The local window tracks project/tab selection and active pane; tab groups separately select visible tabs. [crates/murvix-app-core/src/ids.rs:43–62](../../crates/murvix-app-core/src/ids.rs#L43-L62), [crates/murvix-app-core/src/pane.rs:6–20](../../crates/murvix-app-core/src/pane.rs#L6-L20), [crates/murvix-app-core/src/tab.rs:41–53](../../crates/murvix-app-core/src/tab.rs#L41-L53), [crates/murvix-app-core/src/groups.rs:135–173,274–293](../../crates/murvix-app-core/src/groups.rs#L135-L173).

**Inferred — presentation entities:** these identities support move/focus/close lifecycles, but they are not server execution entities. Closing the last pane closes its tab; empty tab groups disappear. TUI `Tab` instead uses its own pane map/focus/zoom and does not implement all desktop tab attributes. [crates/murvix-app-core/src/state.rs:566–625,690–733](../../crates/murvix-app-core/src/state.rs#L690-L733), [crates/murvix-app-core/src/groups.rs:90–124](../../crates/murvix-app-core/src/groups.rs#L90-L124), [crates/murvix-cli/src/state.rs:35–58](../../crates/murvix-cli/src/state.rs#L35-L58).

## Aggregates and roots: supported limits

**Inferred — catalog consistency-root candidate:** `Catalog::update` serializes writers, clones, applies, validates and persists the entire catalog document containing project/session memberships and operation receipts. Structural invariants therefore have a local synchronous enforcement boundary. However, a rename commit can be published even if subsequent directory sync returns an error. [crates/murvix-server/src/catalog/mod.rs:260–295](../../crates/murvix-server/src/catalog/mod.rs#L260-L295), [crates/murvix-server/src/catalog/storage.rs:7–43](../../crates/murvix-server/src/catalog/storage.rs#L7-L43).

**Not established:** a transactional **Project aggregate** containing processes, Git checkouts, archives and client layouts. Archives are separately persisted; worktree hooks/process termination and Git changes have externally visible effects; natural-exit catalog updates may retry after event emission. Alternate insertion through `finish_git_project` uses final catalog validation rather than ordinary registration's filesystem checks. [crates/murvix-server/src/catalog/git.rs:72–99](../../crates/murvix-server/src/catalog/git.rs#L72-L99), [crates/murvix-server/src/catalog/recovery.rs:13–53](../../crates/murvix-server/src/catalog/recovery.rs#L13-L53).

**Inferred — local application consistency candidates:** `AppState` coordinates cross-project focus/identity/layout validation, while `Tab::validate` ensures layout leaves match panes exactly. Desktop `edit_project`/`edit_tab` restore prior memory on edit/save failure. But public mutable `Project`, `Tab`, `Pane` fields and lower-level `close_tab`/`set_pane_session` mean UI restrictions are not universally enforced by the types. `store::save` serializes without calling whole-state validation. These are not guaranteed encapsulated DDD aggregates. [crates/murvix-app-core/src/state.rs:566–625,979–993,1035–1118](../../crates/murvix-app-core/src/state.rs#L1035-L1118), [crates/murvix-app-core/src/tab.rs:124–144](../../crates/murvix-app-core/src/tab.rs#L124-L144), [crates/murvix-app-core/src/store.rs:50–78](../../crates/murvix-app-core/src/store.rs#L50-L78), [crates/murvix-app/src/model/tabs.rs:78–98](../../crates/murvix-app/src/model/tabs.rs#L78-L98).

**Inferred — composer consistency candidate:** `ComposerStore` owns draft revisions/image references and validates replacement/edit/publication; malformed data blocks overwriting rather than replacing it with an empty draft. Image publication/durability and later terminal input remain separate effects. [crates/murvix-app-core/src/composer/draft.rs:142–163,243–280,334–477](../../crates/murvix-app-core/src/composer/draft.rs#L334-L477). See [BR-11](business-rules.md#br-11-draft-and-submission-preservation).

## Services, repositories, and factories

- **Observed:** `Registry` orchestrates catalog, sessions, archives, activity and operations; `AppModel` orchestrates UI, persistence and server calls. **Inferred:** application services, not pure domain services merely because they enforce some policies. [crates/murvix-server/src/registry.rs:424–589,675–799](../../crates/murvix-server/src/registry.rs#L424-L589), [crates/murvix-app/src/model.rs:872–899,1325–1391](../../crates/murvix-app/src/model.rs#L872-L899).
- **Observed:** `Catalog`, `Archive`, app `store`, extension stores and browser profile adapters persist/access different state. **Not established:** a collection-like DDD Repository abstraction over transactionally defined aggregate roots. Naming these infrastructure responsibilities is more accurate than assigning a repository pattern from filenames.
- **Observed:** `ProjectDescriptor::new/home` construct descriptors and initial metadata; `Tab::terminal/with_content` and layout `Config::build` construct local views. **Inferred:** construction/factory responsibilities, not proof of separate DDD Factory objects. [crates/murvix-protocol/src/project.rs:124–189](../../crates/murvix-protocol/src/project.rs#L124-L189), [crates/murvix-app-core/src/tab.rs:164–184](../../crates/murvix-app-core/src/tab.rs#L164-L184), [crates/murvix-app-core/src/project_layouts.rs:84–102](../../crates/murvix-app-core/src/project_layouts.rs#L84-L102).

Explicit transitions, integration events, callback distinctions and non-guarantees have one canonical home in [workflows](workflows.md#events-and-messages).
